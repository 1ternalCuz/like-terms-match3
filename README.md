# 同类项 · 三消

一款给初中数学课堂用的「合并同类项」互动小游戏。玩法借鉴「羊了个羊」的三消堆叠，
但每一张牌都是一个代数式：**卡槽里凑满 3 张同类项，它们就会自动合并成一张新牌。**

- 单文件、纯离线：双击 `同类项三消.html` 就能玩
- Windows / macOS / 平板浏览器都能跑，不需要安装、不需要联网
- 每关约 **1～2 分钟**，一节课可以完整走完全部 6 关

## 一、怎么开始（Windows / macOS）

### 方法一：直接双击（推荐）

1. 把 `同类项三消.html` 拷贝到 U 盘或桌面
2. 双击它，用浏览器打开（Chrome / Edge / Safari / Firefox 均可）
3. 点「开始合并」即可

> 文件是自包含的：所有样式、脚本、字体回退都在里面，断网也能玩。
> 也可以用浏览器菜单「文件 → 打开」选择它。

### 方法二：从源码构建 / 修改

需要用 Node.js（>= 18）。在项目目录执行：

```bash
node tools/build.mjs          # 由 src/ 生成单文件《同类项三消.html》
node tools/test-engine.mjs    # 引擎测试：74 项
node tools/verify.mjs         # 产物体检：32 项（含 6 个关卡的完整 UI 流程通关）
node tools/browser-check.mjs  # 真实浏览器回归：16 项（需要本机装 Chrome，可跳过）
```

想改题目、改难度，只需要改 `src/engine.js` 里的 `LEVELS`，再重新构建。

## 二、玩法

| 操作 | 说明 |
| --- | --- |
| **读卡面** | 卡片中央就是一个完整的项，如 `6x`；数字下方的斜体 `a` 表示「这是**系数**」 |
| **点牌** | 把一张没有被压住的牌放进下方卡槽（7 个位置） |
| **自动合并** | 卡槽里出现 3 张同类项时，自动合成一张新牌并记下算式 |
| **提示**（H） | 游戏内部有求解器，永远能给出一个「保证能通关」的下一步 |
| **撤销**（U） | 把上一张牌退回桌面，换个顺序再来 |
| **重开**（R） | 重开本关，牌局重新发（同一关卡每次不同） |
| **答案卡** | 默认遮住，让学生先自己算；点一下才揭晓 |

被上层卡片压住的牌会**明显变暗并带斜纹**，点它会被拒绝并提示；
可点的牌是明亮的，鼠标移上去会浮起来——这就是「同一层先清、下面才露出来」的层次感。

### 关键规则

**只有所含字母相同、并且相同字母的指数也相同的项，才是同类项。**

- `3x`、`−5x`、`0.5x` 是同类项 → 可以合并
- `x` 与 `x²` **不是**同类项（字母同、指数不同）
- `x` 与 `xy` **不是**同类项（所含字母不同）
- `−3`、`5`、`8` … 所有常数项互为同类项
- 合并时字母部分不变，**只把系数相加减**

## 三、6 个关卡（一节课的节奏）

| 关 | 名称 | 参与的家族 | 牌数 | 目标答案 |
| --- | --- | --- | --- | --- |
| 1 | 暖身 | `x`、`y` | 6 | `6x + 4y` |
| 2 | 小心 x² | `x`、`x²` | 6 | `8x + 3x²` |
| 3 | 三族同台 | `x`、`x²`、常数 | 9 | `9x + 4x² + 5` |
| 4 | 乘积项 xy | `x`、`y`、`xy`、常数 | 12 | `5x + 6y + 4x·y + 3` |
| 5 | 分数系数 | `x`、常数 | 9 | `5x + 4` |
| 6 | 四族混战 | `x`、`y`、`x²`、常数 | 18 | `12x + 10y + 11x² + 8` |

难度是递进的：

1. **第 1 关**只考「字母一样」；
2. **第 2 关**专门制造 `x` / `x²` 的陷阱——这是本章最容易错的地方；
3. **第 3 关**加入常数项，让学生意识到「没有字母的也算一类」；
4. **第 4 关**加入乘积项 `xy`，考「所含字母都要一样」；
5. **第 5 关**出现 `1/2`、`3/4` 这类分数系数，练分数加减；
6. **第 6 关**四族混合，综合检验。

牌面的系数都是**设计好**的：每一组三张牌的和都恰好是该组能合并出的结果，
所以任何一次合并的算式都又整齐又好念，例如：

```
5x + 6x − 2x = 9x
4y − 3y + 3y = 4y
−2x² + 0.5x² + 2.5x² = x²      （第 5 关）
```

## 四、课堂使用建议（40 分钟）

| 时间 | 环节 | 做法 |
| --- | --- | --- |
| 0–3 min | 引入 | 投屏打开游戏，停在「玩法／知识点」面板，读一遍同类项定义 |
| 3–6 min | 示范 | 老师操作第 1 关，边点边说：「这 3 张都是 x 的一次项，所以只把系数相加」 |
| 6–14 min | 学生体验 | 学生自己玩第 1～2 关；老师巡视，重点看有没有人把 `x` 和 `x²` 放一起 |
| 14–20 min | 讲评 | 投屏某位学生的「合并过程」列表，请学生解释每一步为什么能合并 |
| 20–30 min | 进阶 | 挑战第 3～5 关（分数系数关可以留到最后） |
| 30–38 min | 归纳 | 用第 6 关的答案卡，先让学生自己算最终答案，再点开揭晓 |
| 38–40 min | 作业 | 把答案卡里的 6 个答案抄下来，作为课后小练习 |

### 可以顺势提问的点

- 为什么 `x` 和 `x²` 放不进同一组？（字母相同，但指数不同）
- 为什么 `xy` 不能和 `x` 合并？（所含字母不同）
- 卡槽里剩两张 `x` 却怎么都合不上，问题出在哪里？（同族的牌总数一定是 3 的倍数，
  如果被别的牌挤掉了就凑不齐——这正是「先看清是不是同类项再放」的动机）
- 「撤销」之后重新放，为什么结果反而变了？（合并顺序不影响最终答案，但影响卡槽会不会被占满）

## 五、这个游戏在数学上为什么是「干净」的

游戏不是随机生成题目的，生成过程有三条硬保证（都有自动化测试覆盖）：

1. **每个家族的牌数一定是 3 的倍数。**
   关卡数据里每个家族由若干「三张一组」构成，所以绝不会出现「有一张牌永远配不上」的死局。
2. **每次合并的算式都精确、好看。**
   每组的三个系数都是预先设计好的，和是一个整洁的数（整数或最简分数），
   不会有 `0.3333x` 这种算出来的脏数据。
3. **每一副牌都被证明可解。**
   发牌时用求解器做完整回溯搜索，并在**比实际更小的卡槽容量**下验证可解，
   再用「回放」做二次校验——只有真正走得通的牌局才会发给学生。
   `提示` 给出的走法也来自同一个求解器，所以照着提示点一定可以通关。

自动化测试的实测结论（`node tools/test-engine.mjs`）：

```
引擎测试（74 项全过）每个关卡 30 副牌：
  可解率                30/30
  数学恒等              全部通过（每个家族系数之和 == 关卡答案）
  每族牌数 ≡ 0 (mod 3)  全部通过
  跟着提示通关率         30/30
  发牌耗时               < 20 ms

产物体检（32 项全过）：在浏览器式环境里跑完 6 关完整 UI 流程
  照着提示点一定能通关     6/6 关
  界面上被消除的牌系数和 == 该族系数总和
  牌的可点状态与 DOM 节点一致（防「点了牌不显示、看不出被压住」）

真实浏览器回归（16 项全过，node tools/browser-check.mjs）：在 Chrome 里真的点一遍
  点可点的牌 → 从桌面消失并落进卡槽
  点被压住的牌 → 被拒绝，不落轨
  六关全部在真实浏览器里打通，答案与卡槽算式都正确
```

## 六、项目结构

```
同类项三消.html          ← 最终交付物：单文件游戏（双击即可玩）
index.html             ← 与上面完全一致，供 GitHub Pages 使用（ASCII 文件名）
LICENSE                ← MIT
src/
  engine.js              ← 数学与牌局逻辑：同类项渲染、关卡数据、发牌、求解器
  game.js                ← 界面与交互：卡槽动画、提示、撤销、存档
  template.html          ← 页面结构与全部样式
tools/
  build.mjs              ← 把上面三者合并成单文件 HTML
  test-engine.mjs        ← 引擎测试（74 项）
  verify.mjs             ← 产物体检 + 完整 UI 流程通关（32 项）
  browser-check.mjs      ← 真实浏览器回归（16 项，需要 Chrome）
  design-levels.mjs      ← 关卡设计辅助：搜索「干净的系数组合」
```

改动流程：改 `src/` → `node tools/build.mjs` → `node tools/test-engine.mjs` → `node tools/verify.mjs`。
`build.mjs` 会同时刷新 `同类项三消.html` 与 `index.html`，两者必须保持一致（`verify.mjs` 会校验）。
`verify.mjs` 会校验产物里内联的代码与 `src/` 源码逐字节同源，防止忘记重新构建。
改动界面（尤其卡面布局、可点状态）时，务必再跑一次 `tools/browser-check.mjs`：
假 DOM 抓不到「节点被重建」这类只有真浏览器才暴露的问题。

## 七、常见问题

**Q：双击后浏览器显示空白或提示脚本错误？**
确认文件完整（约 160 KB），并且是用浏览器打开而不是文本编辑器。

**Q：没有声音？**
浏览器要求先有一次交互才允许播放声音，点一下画面即可；右上角可切换静音。

**Q：投屏字太小？**
整个界面按 1180×760 固定舞台等比缩放，用浏览器 `Ctrl/Cmd +` 放大即可。

**Q：想要同一副牌重来一次？**
「重开」会换一副新牌局。发牌用的是随机种子，每局都不一样，所以不必担心学生背答案。

**Q：一节课玩得完吗？**
一关大约 1～2 分钟（有提示的情况下 2～7 次点击就能通关），6 关合计 10 分钟出头，
足够留出讲评和归纳的时间。
